## Response, background failure and current conclusion

Successful responses contain `ok`, `count`, `ids`, `projectedGraphEdges`, `ftsEnabled`, `storageBackend`, `indexed`, `indexing`, `queuedEventVectors` and `queuedGraphNodeEmbeddings` as returned by `events.ts:1011`. The exact empty response is asserted by the contract tests. Counts represent queued inputs, not guaranteed persisted rows or completed embeddings; edge count is the pre-upsert queue length. The combined synthetic fixture intentionally differs only in its textless structural counts: candidate 10 edges / 2 vector tasks / 8 node-embedding inputs versus reference 4 / 2 / 4. This is scoped fixture evidence, not proof of global parity.

Five detached Mongo write failures for non-string IDs are **inherited**, reproduced by the unchanged TypeScript route as well as the candidate: three vector writes reject array `_id` values and two graph embedding writes hit a duplicate multikey index. Both HTTP routes can respond 200 with queued counts while these writes fail. `shape-barrier-{reference,candidate}.log` record the warnings and observed writes; see [the Rheos follow-up](../../kanban/investigate-detached-event-vector-write-failures-failures.md). The reference exposes no complete detached-task handle: its test observes expected warnings, synthetic generator calls and bounded Mongo quiescence, not proof that all later or uninstrumented work is complete.

No currently reproduced candidate-only difference remains in these bounded fixtures after the documented coercion, metadata, collision, missing-runtime and synchronous-lookup fixes. The independent reviewer confirmed the two second-batch fixtures, including the corrected non-vacuous numeric metrics assertion. This does **not** establish complete parity: the explicit gaps above, production configuration and live external services remain blockers. The separate graph lead is the sole writer of the integrated test worktree.

## Additional reviewed coverage

`event_coverage_{candidate,reference}.cljs` samples out-of-order and equal-time predecessors and Unicode slug collisions. In one successful synthetic request, both routes persisted 1,001 label nodes and 1,001 edges in [1000, 1] batches, the numeric ingestion counter rose from 5 to 6, and a spy observed one call to the disabled Kafka plugin. The worker's reviewed run passed 12 candidate and 11 reference checks; these samples do not settle ties, all Unicode values, production scale or live Kafka. Reference detached work remains bounded observation.

For each copied fixture, run from the repository root with `OPENPLANNER_E2E_MONGO_URI=mongodb://127.0.0.1:PORT NODE_OPTIONS='--import tsx' nbb -cp src/cljs:tests tests/openplanner5/event_coverage_candidate.cljs` and substitute the desired test filename. Use a disposable Mongo 7 replica set; see the existing experimental test guide for dependencies and isolation. These scripts compose a test app and do not change the production entry.

Locally testable gaps remain: more attachment and reaction combinations, other scalar/nested JSON shapes, label coercion and Unicode, same-time predecessor ties, failure positions and batch boundaries, and counter/ordering differences under controlled concurrency. Live provider, Clio and Kafka integration, production configuration and clean online dependency installation require appropriate external environments. A product decision is not needed merely to continue local differential coverage.
