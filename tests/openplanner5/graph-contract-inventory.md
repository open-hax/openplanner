# Graph connections contract inventory (local experiment)

Reference: `src/routes/v1/graph.ts`, POST `/v1/graph/connections`, registered through the existing v1 plugin and app authentication/tenant hooks. The local CLJS handler is unserved; test composition selects it during route registration. [Parent story](../../kanban/repair-graph-connection-projection-nections.md); [detached event write follow-up](../../kanban/investigate-detached-event-vector-write-failures-failures.md).

The handler accepts query/text, explicit seed IDs, lake filters, a node cap and desktop visibility options with the reference's aliases, JS coercion, defaults and limits. Seed selection tries allowed explicit seeds, then text index/escaped regex, then recent documents; text-index and regex reads are caught; the recent seed read is uncaught. Tests sample malformed values, filtered seeds, regex escaping and fallback. Authentication, malformed JSON, aliases and unrelated handlers are exercised through loopback HTTP with synthetic configuration, not production credentials.

Traversal performs at most two sequential, unsorted incident-edge finds, each limited to 500, subject to the selected-node cap. Cursor order, node budget, edge-key deduplication and selected endpoints affect output. Hydration separately queries IDs and `extra.node_id`, catches each query failure, and applies the reference collision precedence. Rendering includes node and edge fields, layout, lake/style metadata and bridge statistics; only selected endpoints survive, and bridge output is capped at 20. The endpoint performs no graph writes. A primary traversal read failure produces the reference error response; hydration failures are caught. Existing hydration fallback prefers `extra.user_id` over `author`.

`tests/graph_connections_full_port_probe.cljs` samples all these areas, including two-hop mixed-lake saturation, omitted 501st edge, collision order, independent hydration failures, filtered seed fallbacks and a primary read failure. The latest inventory run had 118 passing assertions; it is not a proof for every query plan, accepted BSON/JS shape, collation, race or error. The combined event/graph test covers five original fixtures; its synthetic environment, detached work, Kafka stub and limited event slice do not establish full serving parity.

The candidate adds cap-edge and author reads. Failures are logged and fall back to reference behavior, so a successful response can still omit an intended correction. A required new read cannot both guarantee corrected data during its failure and retain a reference 200 when no equivalent data is available: propagating failure changes status, while fallback can omit the fix. A different reliable source or architecture could change that tradeoff; this observation does not require snapshot consistency or establish a new public error contract.

`tests/openplanner5/primary_query_probe.cljs` explores an unserved aggregation, not a replacement. A naive lookup under case-insensitive collation conflated authors; global simple collation changed the reference frontier. A type-guarded byte-length plus byte-index expression retained sample case-distinct IDs containing punctuation and Unicode while leaving frontier collation unchanged. On a synthetic 512-document case-insensitive collection with separate source and kind indexes, explain used a frontier collection scan and the kind index for four lookups (24 keys and documents examined). This sample does not establish matching for all data, plans, concurrency or performance. A failed lookup can still change a reference-successful request into an error. No server-side JavaScript or production route wiring was added.

A concrete failure case: with allowed explicit seeds already at the node cap, the reference never starts a frontier read and can return 200 with no edges. If the candidate's additional induced-edge read is unavailable, it cannot obtain the missing edges from that read; propagating its error changes the reference status, while the current fallback returns 200 without the intended correction. This is a data-availability tradeoff, not proof that every possible single-query or alternate-data design fails. Further local work can test additional BSON values, matching indexes, adversarial query plans, contention, timeouts, equal-time bridge ordering and full response equivalence. Those are unverified implementation/verification tasks, not necessarily environment blockers or user decisions.

A further local run compares full HTTP responses for an object seed, empty/whitespace seeds and invalid string timestamps on Discord and generic nodes. It also compares a saturated frontier containing delimiter-colliding edge keys, then checks output against the raw unsorted 500-row cursor. On this indexed fixture only the second collision row was in the cursor, and the 501st inserted row was included; neither insertion order nor this particular plan is guaranteed. The run passed 126 assertions; the initial exploratory run's two insertion-order assumptions failed and remains in the sidecar log. These samples do not establish general malformed-input or query-plan parity.
