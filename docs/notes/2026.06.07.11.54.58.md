sessions is a pretty overloaded word.

While we are migrating data any way, we should change what we call the conversation collections.

Agent "sessions" should be "threads".
This is cleaner than calling them sessions, for the following reasons:
1. while Threads exist as a concept outside of agents, there is only that one other thing that a thread can be, and those have no reason to have a collection created for them.
2. A thread has more relationship to the conversational nature of an user/agent interaction
3. The overlap that does exist to a CPU thread, is semanticly cleaner than to a session in a browser. Agents are basicly smart processes, it's easy to model them the same way you model processes, we even talk about them like this in our Promethean system (the spiral ancestor to this system)
